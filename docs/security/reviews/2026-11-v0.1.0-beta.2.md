## 1. Scope

- **Components reviewed:** the whole project at the reviewed commit, with
  emphasis on everything changed since the previous review:
  - The preview updates in place: it loads its page without content once,
    and the app's script replaces the content of the page's `main` element
    for every new version (`EMPTY_PAGE`, `render_page_content`).
  - The limit on reloads after the preview's web content process ends
    (recommendation of the previous review).
  - A click on a task checkbox renders the preview at once.
  - The mouse pointer over the preview: it is kept when the window's
    title bar changes, and task checkboxes show the arrow. Both changed
    during the review, after a manual test by the maintainer.
  - The link notice appears at once and fades out quickly.
  - The first real run of the release workflow (v0.1.0-beta.1).
- **Changes since the previous review:** #25 (release v0.1.0-beta.1), #26
  (changelog), #27 (snapshot test of the example document), #28 (link
  notice), #29 (preview updates in place, task clicks at once, reload
  limit), #33 and #34 (CodeQL Action and install-action updates, Dependabot
  group for the CodeQL Action), and the pull requests during this review:
  #35 (reload limit while the content is replaced), #36 (the mouse pointer
  is kept when the title bar changes) and #37 (the arrow on task
  checkboxes, which changes the preview's stylesheet and its hash in the
  page's policy).
- **Out of scope:**
  - Local images (v0.2), the folder tree (v0.3), LaTeX (v0.4), Mermaid
    (v0.5) and the Linux app.
  - Distribution to other users: the app is ad-hoc signed and not
    notarized (see accepted risks).

## 2. Threat model

Changes to the [threat model](../threat-model.md):

- System overview: the preview loads the core's page without content once
  and replaces the content for every new version, instead of loading a
  complete page each time. The page, its policy and its stylesheet are
  fixed and come from the core; only sanitized content crosses TB3, as
  before.
- E2 (code execution in the preview): the app runs one fixed script in an
  isolated world; the content is passed to it as an argument, and the
  page's policy and the content blocker apply to the replaced content as
  to a loaded page (#29).
- D1 (resource exhaustion): after the web content process ends, the page
  is loaded again at most twice until the document changes (#29), also
  when the process ends while the content is replaced (#35).
- No new assets, attackers or trust boundaries.

## 5. Attack attempts

Link, task and markup attacks ran through the real WebKit and the app's
preview coordinator, which puts every version into the page in place.
Attacks 16 to 18 put raw markup into the page directly, bypassing the
sanitizer, to test the other defences on their own. Attack 15 ran against
a release build of the app in its sandbox. The attacks ran before #36 and
#37, which change only the mouse pointer; the preview's security tests,
which repeat the request and script attempts in the real web view, pass
on the reviewed commit.

| # | Boundary | Technique | Input | Result |
| --- | --- | --- | --- | --- |
| 1 | TB3 | Forged task link | `markdown-preview://task/<token>/0`, also in upper case, without slashes and as an autolink | `href` removed by the sanitizer |
| 2 | TB3 | Forged task link | `//task/…`, also as `&#47;&#47;` and in a reference definition | `href` removed |
| 3 | TB3 | Path tricks | `../task/…`, `/task/…`, `%2F%2Ftask/…`, `%2e%2e/…`, backslashes, a leading tab, `./task/…` | Resolved below `markdown-preview://document/`; "not supported yet"; never a task action |
| 4 | TB3 | Query and fragment | `?x=//task/…`, `#//task/…` | Below the document address; not supported |
| 5 | TB3 | Scheme confusion | `https:/\task/…`, `https:task/…` | Resolved to `https://task/…`: an ordinary web address; no task action |
| 6 | TB3 | Control | `- [ ] task` | Task action with the version's random token |

## 6. Findings

None. The weakness behind attack 20 has no known attack path: no document
is known that makes the web content process end, so it is documented as
hardening (VAL-2) and was fixed in #35 with a regression test.

## 7. Accepted risks

| Risk | Justification | Review again |
| --- | --- | --- |
| The worst accepted document needs about 2.3 GB: 1.8 GB in the preview's web process and 0.5 GB in the app | Bounded by the node limit; repeated updates in place do not add to it (attack 19); the app stays responsive | Before v1.0 |
| A 50 MB file in a single line takes about 13 s and 2.2 GB to open | Bounded by the file limit; typing is immediate afterwards | Before v1.0 |
| The release is ad-hoc signed and not notarized, so macOS asks before the first start of a downloaded copy | Enough for the maintainer's own use; checksums and attestations prove where the files come from | Before the app is offered to other users |
| A `mailto` link can contain an encoded `@`, so the copied address has two (attack 12) | Nothing is hidden: the notice shows the whole copied text | With the next change to links |

The other accepted risks of the previous reviews still apply.

## 8. Summary

The preview's update in place, the reload limit, the faster task clicks,
the mouse pointer and the link notice meet the checklist.

- **Findings:** none.
- **Hardening during the review:** the reload limit now also holds when
  the web content process ends while the content is replaced (#35).
- **Other changes during the review:** after a manual test by the
  maintainer, the preview keeps the mouse pointer when the title bar
  changes (#36), and task checkboxes show the arrow (#37). Neither
  changes a trust boundary; #37 changes the stylesheet, which the policy
  allows by its new hash.
- **Recommendation of the previous review:** the reload limit is in place
  (#29, #35).
- **Recommendations for the next review (end of v0.2):**
  - Local images: path confinement (FILE-4) and threat I2.
  - Editor highlighting and scroll sync: no document content may reach
    scripts as code.
  - Measure TextKit 2 again with each macOS release.
