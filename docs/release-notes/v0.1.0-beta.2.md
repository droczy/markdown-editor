## Overview

The second beta of Markdown Editor, a native, security-focused Markdown
editor for macOS 26 or later on Apple Silicon. It makes the app feel more
direct, after the maintainer's everyday use of the first beta. Like the
first beta, it is meant for the maintainer's own use and is not notarized
(see *Known issues*).

- **The preview updates in place.** It loads its page once and then only
  replaces the content for every new version of the document, so an edit
  appears at once and the scroll position stays where it is.
- **Task checkboxes react at once.** A click shows the change in the
  preview without waiting for the pause the preview waits for while
  typing. Like other checkboxes on the Mac, they show the arrow pointer.
- **The mouse pointer stays steady.** It no longer turns into an arrow
  or flickers over a link when the document is marked as edited or
  saved.
- **The link notice is quicker.** It appears at once after a click on a
  link and fades out within 0.15 seconds.
- **The preview gives up on a document it cannot show.** After the
  preview's web content process ends, for example because it ran out of
  memory, the preview tries again at most twice until the document
  changes, instead of trying again without limit.

The preview keeps all of its defences: the content that replaces the old
one is governed by the page's Content Security Policy, the content blocker,
disabled JavaScript and Lockdown Mode, exactly like a loaded page.

[FEATURES.md](https://github.com/droczy/markdown-editor/blob/v0.1.0-beta.2/FEATURES.md)
lists everything the app can do and what is planned; the
[example document](https://github.com/droczy/markdown-editor/blob/v0.1.0-beta.2/docs/example.md)
shows the features in one file to open in the app.

## Known issues

- **macOS refuses the first start.** The app is ad-hoc signed and not
  notarized by Apple. Check the download first (see *Verifying the
  download*), unzip it, move the app to *Applications* and open it. When
  macOS says it cannot verify the app, open *System Settings > Privacy &
  Security*, click *Open Anyway* next to the message about Markdown
  Editor, and confirm. This is needed once per downloaded copy.
- **Links are only copied.** A click on a link copies its address to the
  clipboard instead of opening it. Links to headings in the same document
  (`#section`) and to other files only show a notice.
- **Images are placeholders.** The preview shows the image description in
  place of every image; local images are planned for the next version.
- **Very large documents.** The preview shows a notice instead of
  documents larger than 10 MiB or with an extremely large number of
  elements; the editor keeps working. A file of 50 MB in a single line
  takes about 13 seconds to open.
- **An empty preview after repeated failures.** If the preview's web
  content process ends three times for the same version of a document,
  the preview stays empty until the document changes; any edit makes it
  try again.

## Testing

- **CI:** all 12 required checks passed for every merged pull request of
  this beta and for the release pull request, and CI passed again on
  `main` (`5c36504`): formatting and lints, tests on macOS and Linux,
  line coverage of 99.9 % (threshold 95 %), dependency audit, short
  fuzzing, the macOS app build with its security verification and UI
  tests, the workflow audit (zizmor), and CodeQL for Actions, Rust and
  Swift.
- **Nightly** on `5c36504`: 30 minutes of fuzzing (4.1 million inputs)
  without findings; mutation testing with 206 mutants, none missed;
  advisory check of all dependencies.
- **Full security review:**
  [report](https://github.com/droczy/markdown-editor/blob/v0.1.0-beta.2/docs/security/reviews/2026-11-v0.1.0-beta.2.md).
  No findings. The review led to one hardening, fixed with a regression
  test before this beta: the reload limit now also holds when the web
  content process ends while the preview replaces its content (#35).
- **Release files:** packaged and verified locally before tagging; the
  release workflow verifies the app again before packaging it.
- **Manual tests:** the maintainer used the first beta in everyday use;
  this beta addresses that feedback. The maintainer also tested the
  mouse pointer with builds of this beta's changes.
